# Space Sniffer

[English version](README.md)

Нативное приложение для анализа занятого места на диске в реальном времени, написанное на Rust с [eframe / egui](https://github.com/emilk/egui). Выберите любой диск, папку или доступный сетевой путь: карта заполняется уже во время первичного обхода, а затем автоматически обновляется при изменении файлов. Управление и сведения о выбранном объекте собраны в компактной левой панели.

[Скачать последний выпуск](https://github.com/siarheisinelnikau/space-sniffer/releases/latest) · [Измерения производительности](docs/performance.md)

![Space Sniffer: карта занятого места с вложенными папками](docs/screenshot.png)

Это независимая реализация, вдохновлённая [SpaceSniffer от Uderzo Software](https://www.uderzo.it/main_products/space_sniffer/). Проект не связан с Uderzo Software и не использует исходный код или графические материалы оригинального приложения.

## Возможности

- Параллельное фоновое сканирование с прогрессом и отменой: до восьми потоков обхода папок.
- Интерактивная карта растёт уже во время первичного обхода, без ожидания завершения всего диска.
- Автоматическое наблюдение за файловой системой, точечные обновления файлов и восстановление после пропущенных событий.
- Карта прямоугольников с вложенными папками, цветами по типам файлов, настройкой глубины и палитрой Classic.
- Переход внутрь папок, навигационная цепочка, история переходов и панель выбранного объекта со списком крупнейших элементов.
- Фильтры по имени и размеру, копирование пути и открытие объекта в системном файловом менеджере.
- Экспорт текущего поддерева в CSV с исходными размерами и размерами после фильтрации.
- Кнопки выбора дисков, поле корневого пути и начальный экран выбора папки.
- Краткий отчёт из командной строки без открытия окна.

На созданном для проверки дереве из 20 000 файлов в Windows с прогретым кэшем метаданных время сканера сократилось с **292,89 мс до 10,61 мс** по сравнению с прежней последовательной реализацией. Измерены обход, чтение метаданных и сортировка в оптимизированной отдельной программе проверки; это не обещание такой же скорости для целого диска или холодного кэша. Подробности — в [методике и результатах](docs/performance.md).

При сканировании приложение читает метаданные файловой системы. Функции удаления файлов и телеметрии нет. Экспорт записывает только выбранный вами отчёт.

**Платформы:** локальная сборка и проверка выполнены на Windows. В CI настроены сборка и тесты для Linux и macOS; работа их графического интерфейса локально пока не проверена. Сам интерфейс приложения сейчас на английском языке.

## Сборка и запуск

Установите [Rust](https://www.rust-lang.org/tools/install) **1.88 или новее** вместе с Cargo. В репозитории есть `Cargo.lock`; параметр `--locked` сохраняет зафиксированный набор зависимостей.

### Windows

Нужны Rust с инструментами MSVC и Visual Studio Build Tools с компонентом **«Разработка классических приложений на C++»** и Windows SDK. Подробнее — в [инструкции Rust для Windows](https://rust-lang.github.io/rustup/installation/windows.html).

В PowerShell из папки репозитория:

```powershell
cargo run --locked --release
cargo run --locked --release -- "C:\Users"
cargo run --locked --release -- --scan "C:\Users"
```

Первая команда открывает экран выбора корня, вторая сканирует указанный путь и включает наблюдение за изменениями. Режим `--scan PATH` выводит итог и до 20 крупнейших дочерних элементов корня без открытия окна и без наблюдения. Корнем сканирования может быть и обычный файл.

Сборка исполняемого файла отдельно от запуска:

```powershell
cargo build --locked --release
.\target\release\space-sniffer.exe
```

### Linux

Для Debian/Ubuntu установите инструменты сборки и графические библиотеки для X11/Wayland:

```sh
sudo apt-get update
sudo apt-get install -y build-essential pkg-config libx11-dev \
  libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev \
  libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev \
  libgl1-mesa-dev libegl1-mesa-dev libssl-dev
cargo run --locked --release -- "$HOME"
```

См. [требования eframe для Linux](https://docs.rs/crate/eframe/0.33.0). Для графического интерфейса нужны рабочий стол и драйвер OpenGL. Диалоги выбора файлов используют стандартный [XDG Desktop Portal backend библиотеки rfd](https://docs.rs/rfd/0.15.4/rfd/#linux--bsd-backends): нужны `xdg-desktop-portal` и реализация для вашего рабочего стола, например `xdg-desktop-portal-gtk` или `xdg-desktop-portal-kde`. Заголовочные файлы GTK для используемой конфигурации не требуются.

### macOS

Установите Rust и Xcode Command Line Tools (`xcode-select --install`), затем выполните:

```sh
cargo run --locked --release -- "$HOME"
```

При отправке тега `v*` процесс выпуска собирает ZIP для Windows x86-64, tar.gz для Linux x86-64 GNU и tar.gz для macOS на Apple Silicon и публикует их в [GitHub Releases](https://github.com/siarheisinelnikau/space-sniffer/releases). Это архивы с исполняемыми файлами, без установщика или пакета macOS `.app`.

## Управление

Выберите диск, нажмите **Open folder**, введите доступный путь и нажмите **Watch root** или Enter либо передайте путь при запуске. Пока корень не выбран, приложение ничего не сканирует. Сначала появляется корень, затем карта растёт по мере поступления объектов. Выбирать объекты, переходить внутрь папок и фильтровать можно уже во время обхода. Создание, изменение, переименование и удаление файлов затем автоматически отражаются на готовой карте.

Во время обхода **Discovered so far** показывает только уже отображённые данные. Если интерфейс занят, карта может отставать от сканера; это ещё не итоговый размер диска. Группа **Discovered entries** содержит объекты в порядке обнаружения. После завершения обхода предварительная карта автоматически заменяется полным отсортированным результатом; фильтр сохраняется, выбранный объект и открытая папка восстанавливаются, если их пути ещё существуют.

Кнопка **Stop** отменяет обход или останавливает наблюдение, сохраняя текущую карту. Остановленный первичный обход остаётся явно помеченным **Partial map**. **Export CSV** доступен после завершения первичного обхода, чтобы предварительные данные не выглядели полным отчётом. Для завершения остановленного обхода запустите корень снова или выполните повторное полное сканирование.

В левой панели находятся выбор корня, состояние наблюдения, фильтры, глубина, палитра, сведения о выделенном объекте и экспорт. **LIVE** означает активное системное наблюдение; сообщения состояния поясняют восстановление или резервный режим. Геометрия карты кэшируется, а при отсутствии изменений наблюдение не вызывает постоянную перерисовку окна.

| Действие | Результат |
| --- | --- |
| Щелчок по прямоугольнику или строке списка | Выбрать объект и показать сведения |
| Двойной щелчок по папке | Перейти внутрь папки |
| Навигационная цепочка, стрелки назад/вперёд | Перемещаться по результату сканирования |
| `Ctrl+O` | Выбрать папку |
| `F5` | При необходимости повторить полное сканирование корня |
| `Backspace` | Перейти к родительской папке, если вы не редактируете текст |
| **Depth** | Показать от 1 до 6 уровней вложенности |
| **Classic** | Переключить палитру карты |
| **Copy path** / **Reveal** | Скопировать путь / открыть системный файловый менеджер |

Объекты нулевого размера доступны в списке, но не занимают площадь на карте. Во время обхода панель показывает до 100 обнаруженных дочерних объектов, после завершения — до 100 крупнейших.

## Фильтры и экспорт

Фильтры проверяют имя файла без пути и не учитывают регистр. Обычный текст ищется как подстрока. Шаблон с `*` или `?` проверяется по всему имени: `*` означает любое число символов, `?` — один символ. Условия через `;` должны выполняться одновременно. Начальный символ `|` исключает совпадающие имена.

| Запрос | Значение |
| --- | --- |
| `report` | Имя содержит `report` |
| `*.zip` | Имя оканчивается на `.zip` |
| `photo?.jpg` | Имена вроде `photo1.jpg` |
| `\|backup*` | Исключить имена, начинающиеся с `backup` |
| `>100MB` | Размер строго больше 100 000 000 байт |
| `<2GiB` | Размер строго меньше 2 147 483 648 байт |
| `*.zip; >100MB; \|backup*` | ZIP-файлы больше 100 MB, кроме имён с началом `backup` |

`KB`, `MB`, `GB`, `TB`, `PB`, `EB` используют степени 1000; `KiB`, `MiB`, `GiB`, `TiB`, `PiB`, `EiB` — степени 1024. Число без единицы означает байты. Дробные значения, например `>1.5MiB`, должны давать целое число байт. Фильтров по датам и меткам пока нет. Ошибочный запрос показывает сообщение, а предыдущий корректный фильтр продолжает действовать.

**Export CSV** сохраняет все объекты текущего поддерева, включая скрытые фильтром и имеющие нулевой размер. Столбцы: `path`, `kind`, `bytes` и `visible_bytes`. Строки папок содержат сумму размеров потомков, поэтому суммирование всех строк отчёта приведёт к повторному учёту. Пути экранируются по правилам CSV и защищаются от интерпретации как формул электронной таблицы.

## Как считаются размеры и что пока ограничено

- Учитывается логическая длина файлов, а не реально выделенное место. Сжатие, разреженные файлы, метаданные файловой системы и свободное место отдельно не измеряются.
- Жёсткие ссылки учитываются отдельно для каждого пути, без исключения общего хранилища из суммы.
- Символические ссылки и reparse point Windows, включая junction, не обходятся и дают нулевой вклад. Ссылка в качестве корня сканирования вызывает ошибку.
- Недоступные или исчезнувшие вложенные объекты пропускаются и учитываются в счётчике пропусков. Недоступный корень вызывает ошибку. Права доступа не обходятся, поэтому результат может быть неполным.
- Первичный обход папок выполняется параллельно, с ограничением до восьми потоков. В Windows повторно используются метаданные, полученные при перечислении каталога. Скорость зависит от накопителя и структуры дерева; на жёстком диске параллельные обращения могут оказаться медленнее.
- Наблюдение основано на событиях. Неподдерживаемые файловые системы, сетевые ресурсы, права и переполнение очередей могут влиять на доставку уведомлений. При отказе системного наблюдения панель сообщает о резервном режиме: полные снимки проверяются раз в две секунды, а системное наблюдение повторно запускается раз в пять секунд. Для большого корня резервный режим может требовать больше ресурсов. Сканирование не является атомарным снимком файловой системы.
- Полное дерево хранится в памяти. Очень большие деревья могут медленно сканироваться, фильтроваться и отображаться. Отмена кооперативная: она не прерывает уже выполняющийся вызов операционной системы.
